## Описание

Хвост R1.3 (`docs/architecture.md` §1.3, §4). Сейчас личный чат
материализуется при первом обращении к `/chat/` (`ensureChat`) и засыпает
после 15 минут бездействия (TTL reaper, `--chat-ttl-min`). Обратная сторона
модели — UX владельца: после паузы страница прогрева и перерисовка плагинов
(«всё разваливается»). Prewarm-пул = заранее тёплая среда к моменту входа,
управляемая плотность вместо «холодных» стартов.

## План

1. Конфигурируемые TTL/retention per-user (базис: существующий
   `--chat-ttl-min`, `chat.go:479-505`).
2. Prewarm при логине и/или по расписанию: подогрев N последних активных
   пользователей к началу рабочего дня/пары (очередь, лимит пула).
3. Квоты томов и лимит одновременно тёплых рантаймов (плотность —
   `docs/capacity.md` §2).
4. Метрики: hit-rate пула, среднее время первого ответа.

## Критерии готовности

- После длительного простоя первый вход в `/chat/` отдаёт чат без страницы
  прогрева (или быстрее N секунд, цель настраивается).
- Пул ограничен флагами; «все зашли одновременно» не роняет сервер
  (см. `docs/capacity.md` §3).
- Квоты томов настраиваются; e2e покрывает prewarm-цикл (login → тёплый чат →
  TTL-сон → повторный вход).
