## Описание

Ручные кейсы Б8 (D7) и Б9 (D8) протокола РТиППО остаются FAIL на рабочем
стенде: их исправления живут только в ветке `agent/dz2-unit-coverage`,
которая на 30+ коммитов позади main и несёт до-профильную эпоху
(хардкод бренда «ИИ-мастерская ТюмГУ» вместо `window.__AGCTL_BRAND__`).
D6 из той же ветки уже пришлось переизобретать на main (e956694,
chat-brand 0.6.0) — повторить тот же приём для D7/D8. Мерж ветки дороже,
чем воссоздать три маленькие правки.

Кейсы (agctl-hq, `utmn/rtippo_2026/version_2/dz_1/protokol_ruchnogo_testirovaniya.md`):

- **D7 (высокая)**: у роли user агент не в Full access по умолчанию —
  сессия циклично требует подтверждений «Allow this operation with
  danger-full-access permissions»; ожидание: user всегда Full access без
  переключателя, developer/admin сохраняют штатный выбор режимов.
  Механика фикса: `defaultPreset: danger-full-access` в профиле DSH
  только для роли user (в ветке — `provision.EnsurePermissionDefaults`;
  проверка `dsh --dump-config`).
- **D8 (низкая)**: у developer правая панель при старте мигает — пустое
  зарезервированное место, содержимое появляется позже. Механика:
  pre-paint CSS схлопывает колонку до подтверждения роли; плагин не
  открывает пустой rightbar принудительно (уже сделано в chat-brand 0.6.0,
  `syncRoleControls` больше не зовёт `openRightbar`) — осталась
  серверная pre-paint часть.
