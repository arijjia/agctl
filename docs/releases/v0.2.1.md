Исправления локального режима на Linux и мелочи лаунчера.

**Обновление:** поставить бинари заново, затем скачать свежий образ рабочего места:

```bash
curl -fsSL https://raw.githubusercontent.com/arijjia/agctl/main/bin/install.sh | sh
agctl dev update    # тот же тег образа, новая сборка из реестра
```

**Linux**

- Рабочее место работает под пользователем хоста, а не под root: файлы в папке проектов и dsh-home остаются вашими (раньше agctl падал с `permission denied` на файлах dsh-home, а удалять их приходилось через sudo). Файлы dsh-home, оставшиеся от прежних запусков, agctl возвращает владельцу сам. Нужен образ этого релиза (`agctl dev update`); со старым образом место работает под root, как раньше. `AGCTL_CONTAINER_USER=root` — вернуть прежнее поведение.
- Сертификаты организации: в набор для рабочего места попадают и сертификаты, положенные в `/etc/ssl/certs`, `/usr/local/share/ca-certificates` и `/etc/pki/ca-trust/source/anchors` поштучно, а не только общий `ca-certificates.crt`. Раньше хост такому корню доверял, а dsh в контейнере — нет (`SELF_SIGNED_CERT_IN_CHAIN`).
- `agctl dev certs check` проверяет ещё и «как в рабочем месте» — доверяя только набору agctl.

**Лаунчер и рабочие места**

- «Новый воркспейс» на дополнительном рабочем месте создаёт папку в папке этого места (раньше — в папке основного, и создание падало).
- Кнопка «Добавить рабочую область» в локальном режиме скрыта: папку, в том числе вложенный репозиторий, выбирают при создании сессии.
- `agctl dev status`, `logs` и другие команды без `--home` при нескольких домах берут последний запущенный (`agctl dev --home <id> up`).
- Оформление — как в v0.2.0.
