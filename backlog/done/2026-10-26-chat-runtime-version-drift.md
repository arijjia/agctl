## Описание

После `make up` (рестарта на пересобранном образе) чат-контейнер прошлой
сборки мог переживать рестарт серва: новый процесс о нём не знает (кэш
runtime'ов в памяти), TTL-рипер его не усыплёт — контейнер продолжал раздавать
старый dsh web, спасал только ручной `docker rm` (случай 2026-10-26). Дрейф
нужно детектить по фактическому образу: `make up` пересобирает образ под тем
же тегом (`agctl-dsh:0.2.2`), VERSION локальных сборок при этом не меняется.

## План

1. dockerrt: метка `agctl.version` на контейнерах; дрейф по sha образа
   (не по тегу/строке) при создании; `SweepVersionDrift` по префиксу имён.
2. server: `Version` в Config, общий префикс имён чат-контейнеров дома,
   стартовый свип в `New`.
3. Чат-прокси: revalidation для плагинных JS/CSS `/profiles/**`.
4. Тесты: чистые функции (дрейф, кандидат свипа, префикс, revalidate) +
   живой смоук на реальном демоне.

## Критерии готовности

- Контейнеры agctl помечены `agctl.version`; дрейф определяется по sha образа.
- На старте serve свип удаляет chat-контейнеры этого дома, собранные не
  текущим образом; /chat/ пересоздаёт среды лениво, данные на маунтах целы.
- EnsureChat-путь бонсит дрейф по имени до create (не только через коллизию
  «already in use»).
- Плагинные JS/CSS из /profiles/** в чат-прокси отдаются с `Cache-Control:
  no-cache` — обновление плагина доезжает без hard-refresh браузера.
- go vet + go test -race зелёные; живой смоук на демоне: stale удаляется,
  свежий контейнер остаётся.

## Журнал

- 2026-10-26: создано (`gitctl backlog new`).
- 2026-10-26: 2026-10-26: после make up старый контейнер продолжал работать со старым dsh web — пользователю понадобился ручной docker rm. Предложение: на старте serve сверять версию agctl (label на контейнере) с текущей и бонсить дрейф; плюс проверить кэширование /profiles/.../client.js в dsh — обновление плагина требует hard-refresh браузера.
- 2026-11-01: реализовано. dockerrt: метки `agctl.workspace`/`agctl.version`; дрейф — сравнением sha образа контейнера с текущим тегом (`removeDriftedByName` в Start + `SweepVersionDrift` по префиксу `agctl-chat-<hash дома>-`); свип вызывается из `server.New` (дефолтный Docker-конструктор; инъецированные провайдеры не тронуты). server.Config.Version прокинут из `main.version` (ldflags). Чат-прокси: `revalidateProfileAssets` — `Cache-Control: no-cache` для успешных GET JS/CSS из /profiles/** без собственных заголовков кэша рантайма; dsh не форкался — заголовок добавляет agctl-шлюз.
- 2026-11-01: живой тест на демоне 29.9.2 поймал ловушку API moby: в `Summary.Image` — символическое имя (как в docker ps), sha живёт в `Summary.ImageID`; в `InspectResponse` наоборот — `Image` это sha. Свип переключён на ImageID, ловушка задокументирована в коде. Финальный смоук: stale-контейнер (node:22 под agctl-меткой) удалён, свежий (agctl-dsh:0.2.2) остался. go vet + go test -race ./internal/... ./cmd/... — зелёные; полный make up e2e не гонялся (пересборка образа), логика покрыта живым TestSweepVersionDriftLive.
- 2026-11-01: done — Дрейф чат-контейнера детектится по sha образа (не по тегу/строке версии): стартовый SweepVersionDrift сносит хвосты прошлых сборок этого дома, Start бонсит дрейф по имени до create, контейнеры помечены agctl.version; чат-прокси отдаёт плагинные JS/CSS /profiles/** с no-cache. Живой смоук на демоне + go test -race зелёные.
