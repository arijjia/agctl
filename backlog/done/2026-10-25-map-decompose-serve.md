## Описание

Физическая карта (`system/map/agctl-processes.html`, страница `/map`,
`make map`) показывает `agctl serve` одним узлом — владельцу непонятно, что
внутри процесса. Декомпозировать: внутри рамки «Сервер — один хост» сделать
подрамку «agctl serve» с логическими блоками (это блоки одного процесса, не
отдельные процессы — оговорку вынести в подпись/легенду):

- шлюз чата `/chat/` (proxy + mint + чат-шелл + ленивый ensureChat);
- шлюз dev-мест `/w/{id}/` (owner-check + mint + брендинг + страница «остановлено»);
- менеджер чат-рантаймов (карта userID→runtime, TTL-reaper);
- REST API + auth (argon2id, сессии, заявки/апрув);
- хранилище (SQLite WAL) и секреты (AES-256-GCM);
- фоновые горутины (autosave, reconcile, чистка сессий).

Готовая декомпозиция уже написана: `agctl-hq/docs/v3/architecture-explained.md`
§8 (таблица «блок → что делает → код») — перенести узлы и улики оттуда.

## Критерии готовности

- На карте есть подрамка `agctl serve` с перечисленными блоками; у каждого
  блока улики файл:строки (пин коммита).
- Оговорка «блоки одного процесса, не процессы» видна на карте (подпись
  рамки или карточка).
- archify finalize: все 4 гейта зелёные; визуальная приёмка скриншотом —
  без наложений рамок и пересечений.
- `docs/v3/architecture-explained.md` §10 при необходимости синхронизирован.
