## Описание

D6 (пунктирный композер «Выберите воркспейс» на первом запуске) закрыт
unit-тестами плагина (chat-brand 0.6.0, `node --test`) и разовой
Playwright-верификацией, но интеграционного регрессионного кейса в
`tests/e2e-ui` нет: сценарий «чистый браузерный профиль → первый запуск →
активный композер» жил в одноразовых скриптах и умер вместе с ними.
Unit-тесты не ловят классы регресса на стыке с реальным dsh rc.2
(гонки навигации, boot-граф плагинов, живой gateway) — именно там D6
и жил.

## План

1. Добавить в `tests/e2e-ui` (рядом с `cabinet-ui.mjs`) сценарий
   `first-session-ui.mjs` + обвязку в `bin/e2e-cabinet-playwright.sh`
   (или отдельный bin-скрипт): изолированный TEST_HOME, демо-юзер,
   свежий browser context (localStorage пуст — «чистый кэш» из кейса Б7).
2. Утверждения:
   - после загрузки /chat/ (терпимо к ленивому старту контейнера:
     503-ретраи, таймаут ≥150 с) `[data-composer-input]` имеет
     `contenteditable="true"`;
   - `data-conversation-session` не пуст (сессия открыта);
   - в консоли нет фатальных ошибок класса D6-эпохи
     (`found is not defined`, `setEnabled is not a function`);
   - чип воркспейса показывает папку, а не плейсхолдер.
3. Второй сценарий — «застрявший выбор»: чип с папкой при отсутствии
   сессии самоактивируется ≤5 с (лечебник `healStuckWorkspacePick`).
4. Прогон одной командой, изоляция портов/домов как в существующих e2e,
   очистка контейнеров по маунт-префиксу TEST_HOME.

## Критерии готовности

- `bin/e2e-*.sh` прогоняет оба сценария зелёно на свежем стенде.
- Кейс ловит регресс: на сборке ДО e956694 (chat-brand 0.5.0) падает,
  после — проходит (проверить на двух git-ревизиях).
- Сценарий упомянут в README tests/e2e-ui.
