## Описание

`bin/e2e-smoke.sh` целиком проверяет v2-воркспейсы, удалённые в v3:
`POST /api/workspaces → 410 «Рабочие места удалены в v3»`. Поэтому
еженедельный cron `dsh-bump` давал гарантированно красный запуск
(3/3 с 19.10), и в e16fce9 расписание снято — остался `workflow_dispatch`.
Без гейта автоматический апдейт пина DSH не работает: каждый понедельник
приходится помнить и гонять `gh workflow run dsh-bump` руками.

Переписать смоук под v3-модель: персональный контейнер + проекты
(вместо create/wait-running/stop/start воркспейса — вход, проект-папка,
персональный контейнер, его сон/пробуждение). Сохранить удачные части:
fake-llm стаб, раннюю диагностику serve (fc16165), изоляцию ролей,
живой провод до модели.

Браузерный продуктовый e2e — отдельная карточка
`v3-product-e2e-playwright`; эта — про curl-смоук как CI-гейт.

## План

- Составить v3-сценарий по коду API (какие эндпоинты живут в v3).
- Переписать `bin/e2e-smoke.sh`: этапы, проверки, диагностика.
- Прогнать локально до зелёного, затем в CI (`workflow_dispatch`).
- Вернуть cron в `.github/workflows/dsh-bump.yml` (снят в e16fce9).

## Критерии готовности

- `bin/e2e-smoke.sh` проходит локально зелёно на текущем образе.
- `gh workflow run dsh-bump` проходит целиком (при изменившемся пине —
  с e2e-гейтом и созданным PR).
- Cron снова в расписании; карточка закрыта.
