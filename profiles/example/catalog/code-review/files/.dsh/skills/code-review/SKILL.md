# Ревью кода по правилам команды

1. Посмотри изменения: `git status`, затем `git diff` (или `git diff main...HEAD`).
2. Пройди чек-лист:
   - у изменённого поведения есть тест, и он проходит;
   - в коде, логах и тестовых данных нет секретов и персональных данных;
   - публичные функции и флаги описаны там, где их ищут (README, справка);
   - нет закомментированного кода и случайных отладочных выводов.
3. Ответь списком находок: файл и строка, в чём проблема, что предлагаешь.
   Если замечаний нет — так и скажи, без общих слов.

Это пример. Замените чек-лист правилами вашей команды.
