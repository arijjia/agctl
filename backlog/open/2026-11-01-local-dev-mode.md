## Журнал

- 2026-11-01: создано (`gitctl backlog new`).
- 2026-11-01: Дизайн-дока и решения: agctl-hq/docs/v3/local-dev-mode.md (коммит cb0c660). Ключевые решения: нативный стек (без Docker) основной — требование полного доступа к машине несовместимо с изоляцией, а она единственная причина Docker; Docker — опция фазы 3 для закрытых машин; фронт локальный (127.0.0.1 + boot-токен, механика из agctl local connect --launch-dsh), сервер остаётся control plane'ом (аккаунты/роли/профиль/пины/брокер токенов); данные - источник истины ноутбук (DSH_HOME ~/.agctl-dev), чат-истории на сервер не утекают; LLM-доступ через device-flow брокер короткоживущих токенов (как gh auth) вместо статики в профиле; кроссплатформенность = Go-бинарь + managed Node по пину из профиля, dsh не форкаем. Фазы: Ф1 проверка ценности (init/up/down на системном Node) -> Ф2 managed Node + dev login + allowlist -> Ф3 флит/Docker-опция -> Ф4 опциональный мост-фасад (паркованный internal/bridge, отдельной карточкой). Открытые вопросы владельцу в §10 доки (Windows в пилоте? allowlist по умолчанию? центральный индекс сессий? популяция Docker-машин?).
- 2026-11-02: Дизайн-дока дополнена §11 «Пользовательский сценарий» (agctl-hq 82f72dc): разработчик видит на сервере тот же дефолтный чат (общий слой, работает с любого устройства) плюс новый блок Кабинета «Локальная среда» (заявка роли, скачивание под его ОС, чеклист); новая серверная деталь - статический /download/ (бинарь + SHA256 + install.sh); порядок: dev init (логин + засев профиля) -> dev up ~/src/proj (127.0.0.1 + boot-токен) -> работа в родных файлах -> dev down; сервер видит факты (устройство/токен/версия), не контент.
- 2026-11-02: Дизайн-дока дополнена §12 «Квоты, брендинг и граница доверия» (agctl-hq): принуждение живёт там, где ресурс - локальный ноутбук не квотируется, деньги и доступ квотирует сервер через брокер токенов; managed-слои бренда/плагинов переписываются при каждом dev up (идемпотентный засев как на сервере), user-слои не трогаются; version gate при refresh токена; инвентарь control plane по пунктам (идентичность/роли/устройства, брокер LLM, профиль+пины, дистрибуция, серверный чат, Кабинет, аудит).
