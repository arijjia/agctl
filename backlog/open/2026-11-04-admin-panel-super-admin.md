## Описание

Требование владельца 2026-11-04 (устно, запись в agctl-hq). Админка — отдельная
страница agctl (React), открывается роли `admin` сразу после авторизации.

**Смена роли admin**: admin — не пользователь платформы. Личный dsh-контейнер админу
не поднимается никогда; `/chat/` для admin закрыт. Роли продукта: `user`,
`developer` (+ служебный `admin` с доступом только в админку).

**Статистика по пользователям**:
- сводка: сколько пользователей, сколько живых контейнеров, сессии, потребление;
- активность по пользователям (последняя активность, live-контейнер, том, TTL);
- мониторинг контейнеров: список agctl-контейнеров (юзер, образ, статус, память/CPU);
- управление контейнером: стоп/старт/рестарт из админки;
- детальный мониторинг по пользователю: сессии и их содержимое.

**Прозрачность действий агентов**:
- отдельная страница: ВСЕ запросы пользователей через шлюз в том виде, в котором
  приходят (метод, путь, юзер, статус, время);
- отдельная страница: траектория агента по сессии (как trajectory-view в самом
  Harness) — чтение сессий dsh из персонального тома на хосте.

**Квоты и ресурсы**: LiteLLM-ключ один на всю платформу → управлять квотами
(бюджеты токенов) на роли / группы / отдельных пользователей нужно на стороне
платформы. Плюс управление ресурсами (лимиты контейнеров, TTL).

## Критерии готовности

- [ ] `admin` после логина попадает на `/admin`; `/chat/` и личный runtime админу недоступны
- [ ] сводка+список пользователей с состоянием контейнера/тома
- [ ] список контейнеров и операции стоп/старт/рестарт
- [ ] страница «запросы»: журнал проксированных запросов per user
- [ ] страница «траектории»: сессии пользователя из тома, просмотр содержимого сессии
- [ ] квоты: задание бюджетов per user/role в админке (хранение в SQLite)
- [ ] e2e/тесты на admin-API; go vet/test зелёные; SPA собирается

## Не делать

- Не выдавать админу личный dsh-контейнер ни в каком сценарии.
- Не публиковать admin-API без requireAdmin.
- Не ломать существующие контракты ChatProvider / маршруты user/developer.
