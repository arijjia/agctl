# Скилл: 1c-vibe-demo — «задача из Jira → Merge Request → комментарий»

## Когда применять

Пользователь просит: «выполни задачу INTAIDEV-N», «сделай MR по задаче INTAIDEV-N», «возьми тикет и сделай».

## Процедура (строго по шагам)

1. **Прочитай задачу.** Выполни из каталога `scripts/`:
   ```
   python3 jira_client.py get INTAIDEV-N
   ```
   Выпиши для себя: что просят изменить, в каком объекте, какие критерии приёмки.

2. **Подготовь рабочую ветку до любых правок.** Если клона нет — склонируй
   демо-репозиторий в `scripts/dump/1c-vibe-demo` (адрес возьми из `.env`
   `DEMO_PROJECT` + хост `GITLAB_URL`, или спроси пользователя). Затем из
   каталога `scripts/` выполни:
   ```
   python3 publish.py INTAIDEV-N --repo <путь к клону> --prepare
   ```
   Команда проверит чистоту рабочей копии и создаст `agent/INTAIDEV-N` от
   актуальной основной ветки. Работай ТОЛЬКО в этой ветке.

3. **Найди нужные файлы.** Дерево устроено как выгрузка конфигурации 1С:
   - `Configuration.xml` — корень, список всех объектов;
   - `Catalogs/<Имя>/Object.xml` — описание справочника (реквизиты и пр.);
   - `Catalogs/<Имя>/Ext/ObjectModule.bsl` — модуль объекта (язык BSL);
   - `Catalogs/<Имя>/Ext/ManagerModule.bsl` — модуль менеджера.
   Выбирай файлы по смыслу постановки; если непонятно, какой объект править, —
   спроси пользователя, НЕ выдумывай.

4. **Сделай минимальную правку.** Стиль — как в окружающем коде. Для BSL:
   русский синтаксис языка 1С, таб-отступы, комментарии к экспортным функциям
   в формате `// Параметры: ... // Возвращаемое значение: ...` (стандарты 1С).
   Новые реквизиты описываются в `Object.xml` в разделе атрибутов объекта.

5. **Проверь себя.**
   - Перечитай дифф (`git diff`) глазами: правка соответствует постановке?
   - Прогони линтер через `python3 lint.py --src <путь к выгрузке>` (jar
     скачается сам, pin-версия; отчёт fail-closed). Ошибки уровня Error
     исправь, предупреждения оцени. Альтернатива — команда из
     `demo-project/README.md`.
   - **Если машина с контуром 1С** (есть `win\contour-*.ps1` и настроенный ibcmd) —
     прогони цепочку `contour-restore → contour-import → contour-check`
     (PowerShell); лог проверки приложи к MR как пруф. Ошибка любого шага =
     правь код, а не публикуй. Если контура нет — достаточно линтера (MVP-режим).
   - Не оставляй в диффе мусор: временные файлы, отладочную печать
     (`.bsl-ls/`, `audit.log` в коммит не брать).
   - **Если постановка содержит критерии «Когда/Тогда»** — приложи к MR
     Vanessa-сценарий (Gherkin-подобный текст, клиент тестирования 1С):
     один сценарий на критерий, шаги «Когда … Тогда Ожидаем …». Сценарий
     добавь в описание MR текстом (запуск — на контуре, Фаза 3).

6. **Опубликуй.** Из каталога `scripts/`:
   ```
   python3 publish.py INTAIDEV-N "резюме правки одним предложением" --repo <путь к клону>
   ```
   Скрипт проверит, что агент находится в подготовленной ветке, затем закоммитит,
   запушит, откроет MR и добавит комментарий в Jira. В выводе будут ссылки.

7. **Доложи.** Дай пользователю: ссылку на MR, ссылку на задачу, краткое
   описание правки и что проверено. Если что-то не получилось — честно скажи,
   на каком шаге и с какой ошибкой.

## Правила безопасности

- Никогда не пушь в основную ветку напрямую — только через `publish.py` (MR).
- Не коммить `.env` и любые токены.
- При неоднозначной постановке — задай вопрос, а не выбирай трактовку молча.
- Если задача не про демо-репозиторий (упоминаются реальные системы, прод, БД) —
  остановись и уточни у пользователя: реальные задачи обрабатываются другими скиллами.
