## Описание

Требование владельца 2026-11-04 (устно). Для роли `developer` после авторизации
контейнер НЕ запускается автоматически: вместо чата открывается мини-админка
(лаунчер), на которой разработчик:

- выбирает образ, с которого запуститься (в университете есть Nexus; список
  готовых образов — из конфига serve); кейс для демо: «образ №1 без SSH» и
  «образ №2 с SSH»;
- видит все свои запущенные контейнеры (образ, статус, порт) с операциями
  стоп / старт / рестарт;
- опционально (позже): несколько контейнеров на одного developer (редкий
  кейс) — пока v1 один персональный runtime с выбором образа и пересозданием.

Обычный `user` ведёт себя как сейчас: сразу личный контейнер дефолтным образом.

## Критерии готовности

- [ ] developer после логина видит лаунчер, контейнер не стартует до выбора
- [ ] список образов из конфига serve (в т.ч. реестр Nexus по HTTPS)
- [ ] запуск выбранного образа; смена образа пересоздаёт контейнер на том же томе
- [ ] список своих контейнеров: образ/статус/порт + стоп/старт/рестарт
- [ ] API под requireUser(developer|admin); go vet/test зелёные; SPA собирается

## Не делать

- Не менять поведение роли `user` (ленивый дефолтный запуск как сейчас).
- Не давать developer управлять чужими контейнерами.
- Не хранить креды реестра в образе/гите (только конфиг/env serve).
