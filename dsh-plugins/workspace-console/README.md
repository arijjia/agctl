# @arijjia/agctl-workspace-console — консоль воркспейсов (возможности, промт, компоненты)

Клиент-плагин dsh web. Единое место настройки воркспейсов для всех ролей:
список проектов пользователя, у каждого — три раздела:

1. **Возможности** — платформенный каталог пакетов (`GET /api/projects/<name>/catalog`):
   навык + шаблоны/скрипты одним кликом (например, «Презентации по шаблону
   вуза»). Пакет ставится в `.dsh/skills/<name>/` воркспейса — dsh подхватывает
   такие скиллы сам (проектные корни скиллов: `.dsh/skills`, `.agents/skills`).
2. **Системный промт** — текст `AGENTS.md` воркспейса (`GET/PUT …/prompt`),
   один на воркспейс; пустой промт удаляет файл.
3. **Компоненты** — каталог скиллов/инструментов/данных/промптов с галочками
   включения (`GET/PUT …/components`); скиллы в `skills/` и в `.dsh/skills/`
   (kind `dshskill`, бейдж «автозагрузка») группируются вместе.

Тот же каталог пакетов показывается при создании воркспейса (диалог
chat-brand) — один и тот же серверный механизм, одно место правды: выбрал при
создании — меняешь потом в консоли, и наоборот. Настройки не валиваются в
момент создания: сначала создаётся воркспейс, сценарий настраивается потом
и динамически.

**Удаление воркспейса** — кнопка «Удалить» на карточке проекта: каталог
проекта на диске стирается (`DELETE /api/projects/{name}`, безвозвратно,
после confirm), затем снимается запись нативного реестра dsh (через штатный
сервис `workspaces.delete`; каталог уже удалён, так что одноимённый
`POST /api/projects` снова работает). Для «сироты» — каталог без записи
реестра (остаток старого нативного удаления dsh, которое каталог хранил) —
достаточно agctl-ручки. Нативное удаление в сайдбаре dsh тоже удаляет
каталог: chat-brand оборачивает `workspaces.delete` тем же agctl-вызовом.

## Контракты

- `GET /api/me` — чип консоли виден всем ролям (user/developer/admin);
  у админа личных воркспейсов нет, список будет пустым.
- `GET /api/projects` — список воркспейсов-проектов.
- `GET /api/projects/{name}/components` — каталог компонентов: id, kind
  (skill|dshskill|tool|data|docs), title, description, path, enabled, locked.
  Истина о состоянии — рабочее дерево проекта.
- `PUT /api/projects/{name}/components` с `{"disabled":[...]}` — применить
  выбор на сервере: выключенные компоненты переносятся в
  `/workspace/<name>/.agctl/stash/` (stash не виден агенту и не коммитится
  autosave'ом), включённые возвращаются. Репка-донор не правится.
- `GET /api/projects/{name}/catalog` — пакеты платформы со `installed`.
- `POST /api/projects/{name}/catalog/{id}/install` — установить пакет
  (файлы 1:1; переустановка = обновление до версии каталога).
- `DELETE /api/projects/{name}/catalog/{id}` — убрать пакет; изменённые
  пользователем файлы не удаляются (сообщение в кнопке).
- `GET/PUT /api/projects/{name}/prompt` — AGENTS.md воркспейса
  (`{"prompt": "..."}`; пустой/пробельный промт удаляет файл).
- `DELETE /api/projects/{name}` — удалить каталог воркспейса с диска
  (идемпотентно: «уже нет» = 200; чужое имя не адресуемо — у другого
  пользователя просто нет такого воркспейса).
- Граница доступа: все ручки работают только с СВОИМИ воркспейсами
  (чужое имя = 404, каталоги строго внутри личного тома).

## Реализация и проверка

`lib/client.js` — hand-written Lazy-CJS bundle, React/DSH API не форкаются.
Чип регистрируется в штатном слоте `sidebar.footer.action` (order 11, под
чипом кабинета). Тесты: `node --test` в каталоге плагина (shouldShowChip для
всех ролей, groupComponents с dshskill, buildDisabledIDs). Embedded-копия в
`internal/assets/dsh-skel/...` совпадает побайтно (гвард в internal/assets).
