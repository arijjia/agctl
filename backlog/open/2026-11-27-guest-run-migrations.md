## Описание

Обновление рабочего места сейчас — смена образа и перезапуск: dsh сам
мигрирует сессии, а файлы, которые раскладывает agctl (пресеты, скиллы,
плагины, settings.yaml), переписывает хост на каждом старте. Нет места,
где образ сам проверяет и мигрирует свой dsh-home, и нет метки версии
состояния — откат на старый образ после миграции ничем не страхуется.

## Что сделать

- `agctl run` в guest: мини-доктор (dsh на месте, DSH_HOME пишется,
  версия node), миграции dsh-home по метке `$DSH_HOME/.agctl/state-version`
  (по порядку до версии образа), затем `exec dsh web` с нынешними флагами.
- entrypoint: есть `agctl run` — запускает его; нет — прежний путь
  (совместимость образов без guest и чистого dsh).
- Метка версии состояния и правило отката: миграции не ломают чтение
  прежней версией, иначе откат требует бэкапа (agctl dev update уже
  делает бэкап основного места; для дополнительных мест — тоже).

## Критерии готовности

Переключение места между образами двух версий туда и обратно проходит
без ручных шагов; лог старта показывает версию состояния и миграции.
